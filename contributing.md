# Contribution Guidelines

Thanks for helping improve the list. Please keep it useful for engineers choosing and learning tools.

## What belongs here

- Tools, services and resources about moving, transforming, orchestrating or validating data.
- Open source projects that are maintained: a release or meaningful commit in the last 12 months.
- Managed services with public documentation.
- Learning resources that teach something durable, not product announcements.

## What does not belong

- Marketing pages, listicles or vendor comparison posts.
- Archived or abandoned projects.
- Duplicates: one entry per tool per section. A tool may appear in more than one section only when it is a primary choice in each.

## Format

- One entry per pull request.
- `- [Name](link) - Description.`
- Link to the project's repository for open source tools and to the product page for managed services.
- Keep descriptions short, factual and neutral. Say what the tool does, not why it is the best. Avoid words like "awesome", "best", "leading" or "blazing".
- Start the description with a capital letter and end it with a period.
- Keep entries in each section in alphabetical order.
- Check spelling and grammar, and remove trailing whitespace.

## Pull requests

Give the pull request a title like `Add Project Name` and say in one sentence why it is useful. Pull requests that change many entries at once are hard to review; please split them.

Please note that this project is released with a [Contributor Code of Conduct](code-of-conduct.md). By participating in this project you agree to abide by its terms.
